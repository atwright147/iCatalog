# iCatalog v0.2.0

iCatalog now provides secure NAS sync with durable conflict recovery, a native
stored-preview viewer, and documented Linux service setup.

## Changes

- HTTPS and shared-token authentication for servers and clients, including
  desktop Security file pickers and optional remembering of file paths.
- Opt-in sync checks when opening a catalogue, an explicit read-only browsing
  choice, and durable field-level conflict resolution. Interrupted replacements
  can be verified and resumed; local drafts remain preserved.
- Double-click an asset or choose View preview to inspect its stored JPEG in
  Fit or 100% view. Embedded and cached previews work without original media.
- Static CLI-only NAS archives for Linux x86-64 and ARM64, alongside the existing
  Windows, macOS ARM64 and Linux desktop packages.
- A restricted systemd unit, optional HTTPS drop-in and explicit installation,
  maintenance, upgrade and removal instructions.

## Install and upgrade

Download the package matching your OS and CPU and verify it against `SHA256SUMS`.
NAS archives contain the standalone `icatalog` executable. The source archive
contains `packaging/systemd/icatalog.service` and `packaging/systemd/https.conf`;
follow [the service guide](../nas-service.md) or [Docker/Compose setup](../nas-docker.md).

Before upgrading, stop the server and other writers, back up the entire catalogue
directory (including external previews and sync companion files), and retain the
old executable. Upgrade server and clients together. Preserve newer work before
any rollback; use the matching pre-upgrade catalogue backup if a newer release
has migrated it. Existing `.sqlite` catalogues remain supported alongside
`.icatalog` files.

## Current limits

- Previews are at most 1920 pixels on the long edge. Generate them explicitly
  where original media is available. External previews must be fetched with the
  CLI `sync --preview` command before the desktop can view them.
- Automatic background sync, incremental catalogue downloads, container registry
  publication and automatic certificate renewal are not included.
- Conflicts involving entities deleted on the server remain preserved but cannot
  yet be resolved through the field-choice workflow.
- macOS packages are ad-hoc signed, without Developer ID notarization; Windows
  publisher signing is not configured. No macOS Intel package is supplied.

See [sync setup and recovery](../sync-user-guide.md) for everyday use.
