# iCatalog roadmap

Purpose: what is built, what is in progress, and what comes next, app-side. Crate map and layering live in `docs/architecture.md`; numbered decisions in `docs/decisions.md`; the format study in `ivc-file-research/AGENTS.md`. Status vocabulary: **Decided** (owner order), **Proposed** (breakdown), **Open** (unresolved). The exit criteria for every milestone are the workspace gate: `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings`.

App-side crates that exist today: `icatalog-catalog`, `icatalog-media`, `icatalog-engine`, `icatalog-sync`, `icatalog-cli`, `icatalog-ui` (plus `ivc`, in `ivc-file-research/`).

## 1. Priority rule

**Decided:** format knowledge first, then the data model, then the interfaces. App-side order: schema, engine + CLI, sync, egui (desktop, then wasm); M4 was pulled ahead of M3 by owner request (D15). Crash-safety fixes outrank feature work (golden rule).

## 2. Done

- **M0 housekeeping** — repo under git; root `.gitignore` (`target/`, `log/`, `*.sqlite`); `crates/*` workspace members; `log/devlog.md` (local, gitignored).
- **M1 schema** — `icatalog-catalog`: schema v1-v6 with migrations, the model + CRUD for every table (including `source` with device provenance and source-rooted folders, D21), `AssetQuery`/`CatalogStats`; round-trip, FK-cascade, constraint, raw-bytes, migration and never-panic tests. The one open piece — the `ivc` import mapping — is M2 work, not schema work.

## 3. In progress

- **M2 engine + CLI** — *landed:* the `icatalog-engine` command registry + `dispatch_guarded` panic guard; the `icatalog` commands `init`, `open`, `import` (D13, now source-rooted folders with `--kind`, D21), `list`, `find`, `status`, `update` (D14, offline sources are not marked missing, D21), `edit` (D16) and manual `collection` actions (D25, including `list`/`find --collection`); the layer test; `icatalog-media` raster ingest (`image`), EXIF (`kamadak-exif`) and grid thumbnails; per-reason skip reporting in `import`/`update`; the adversarial-params fuzz test (`crates/icatalog-engine/tests/adversarial.rs`). *Open:* a `source`/`folder` command surface, legacy `.ivc`/`.mpcatalog` import (deprioritised) and the PICT pixel decoder (`ivc` work, tracked in `ivc-file-research/AGENTS.md`).
- **M4 egui (desktop)** — *landed:* `icatalog-ui`, a thin native egui shell (D15) that browses assets, shows a stored thumbnail + metadata, edits rating/label/keywords, and dispatches `init`/`import`/`update`/`edit`/`collection` as engine commands. The left panel has a source-rooted folder tree grouped under collapsible device headers (D21; selecting a device shows all its sources' assets), the centre a grid/list view with search, and the right a details panel. Manual Collections can be created through the sidebar's New Collection modal (D26), show catalogue-wide asset counts (D30), and are selected in the sidebar, with grid/list drag-and-drop (D27), multiple asset selection and tri-state collection membership checkboxes in the context submenu (D29). Shift-click ranges and Ctrl/⌘-click toggles combine selected collections without duplicate assets (D28). *Open:* recursive folder selection, and the wasm build (trunk + wasm-bindgen; the target is not installed and no wasm status is claimed).
- **M3 sync** — *landed (D18):* the `icatalog-sync` crate with the NAS-side HTTP service (`serve`: `GET /info`, `GET /catalogue`, `POST /catalogue?expected=`) and client (`sync`: generation-guarded push/pull, refuse-and-resync, timestamped backup before any overwrite, temp-file + integrity check + atomic swap); offline is deferred, never fatal. A local change marker (D19) makes an idle re-sync a no-op (no push, no generation bump); any local edit is still pushed. `sync`/`serve` are wired into the `icatalog` CLI (the shell merges the engine and sync registries) with tests for a round trip, a refused push (backup + resync), an invalid snapshot, offline deferral, hostile params, an idle re-sync and a pushed local change. *Decided target (D20, **not built**):* the model moves from bidirectional whole-snapshot to **server-authoritative with an annotation-delta push** (rating/label/keywords keyed by stable asset uid; never media or previews) and **content-addressed, pull-only previews** (`GET /preview/<sha>`), with the preview store chosen per catalogue — embedded for a portable single-file `~/Pictures` catalogue, external for the NAS. See `docs/sync.md` (Target model) and D20. *Open:* the D20 slice below; TLS and auth; delta/incremental transfer; conflict merge.
- **Media breadth (D8/D17)** — *landed:* EXIF-oriented thumbnails with display fallback for older catalogues (D31), RAW embedded-preview thumbnails, RAW container format + true dimensions, and XMP packet storage with seed-on-first-ingest of rating/label/keywords — with no new dependencies (D17, D31). *Open:* sidecar `.xmp`; PSD; HEIC/AVIF (metadata only); video metadata + frame (FilmCraft); the preview store (D8's derived disk preview cache, now scoped by D20 as the per-catalogue embedded-or-external preview store with a 1080p+ tier — not built). No demosaic, by design.

Smart Collections (D35) are implemented in the catalogue, engine/CLI and desktop: typed AND rules for format, capture dates, camera/lens, rating/label, keyword and filename/path text; live membership/counts; mixed collection unions/search; create and replace-rule commands; modal creation and right-click rule editing. Schema v6 preserves existing manual collections. OR groups, nested rules and manual-to-smart conversion are not included.

Smart Collection previews (D37) show a live catalogue-wide match count and readable AND summary in Create/Edit Rules before saving. The same read-only preview is available through `collection preview-smart`. Background previews debounce typing, discard stale results and report invalid rules/read errors; long summaries scroll while fields and buttons remain visible in 800×600 windows. No schema or sync change.

All collections can be renamed (D36) through `collection rename` or the sidebar's right-click Rename… modal. Renaming preserves ids, membership, rules, counts and active selections; failures retain the entered name for retry. No schema change.

Smart Collection names and rules can be edited together (D38) through the shared editor and optional `set-rules --name`. Double-clicking a Smart Collection selects it and opens Edit Rules; Save/Enter commits both changes atomically. Invalid input/failures retain the draft; pending commands block opening another editor. Normal Collections open Rename on double-click (D41). macOS double-click timing follows the system preference with a 500 ms fallback (D39); slower-click and batched-input regressions supplement the original fast-click tests.

Smart Collection selection stays stable between double-clicks (D40): only plain-click deselection of an already selected smart row is deferred until the double-click interval expires. New selections and modifier gestures remain immediate. D41 extends the same behavior to normal Collections, whose double-click opens Rename with the current name selected. Tests assert collection and asset selection between clicks and cover cancellation of obsolete toggles, rename/Enter/cancel/reopen and busy guards.

D23 hardening is implemented: atomic engine command dispatch, reported UI refresh/startup errors, background import/update/edit/collection, visible-row rendering and bounded thumbnail caching. Regression coverage includes partial writes, panic/commit rollback and 10,000-row viewport bounds; `task scale` adds opt-in generated-image and sync workloads. Remaining scale work includes asset-query paging, asynchronous visible-thumbnail decoding, per-file progress/cancellation and representative RAW-library benchmarks.

D24 UI checks exist: real-widget interaction/persistence tests in the workspace gate, opt-in GPU screenshot comparisons (including populated/multiple collections, creation modal, context menu, drop target and long-name collection counts, D25-D30), and a separately invoked native macOS menu/picker-cancellation/quit smoke test. Regression coverage includes membership-cache invalidation and busy/read-error handling, count/name spacing and rectangle selection while scrolling. Local and hosted workspace/visual checks passed. Two inspected Linux screenshot failures were tiny thumbnail colour-rounding differences; only those snapshots use a measured colour tolerance of 1.0 on Linux, keeping 0.6 elsewhere and zero failed pixels. Baselines remain unchanged; manual self-hosted execution and broader native interaction/platform coverage remain open.

The native Update smoke timeout is resolved: the test uses a unique temporary app identity with guarded PID targeting to avoid confusing another running iCatalog, and waits for foreground/menu readiness and picker dismissal. Three consecutive final local smoke runs passed Update persistence, Import cancellation and Command-Q; the workspace gate passed. Automation stage logs now survive failures/timeouts. Self-hosted native workflow execution remains unverified.

List rows (D32) show thumbnails plus filename/rating/captured and modified dates/filesize; document/camera/lens/focal length; dimensions/colour/ICC profile. List uses the browsing width, an optional Details inspector, and horizontal scrolling in narrow windows. Import/update capture supported source colour information, and Update fills older entries without regenerating unchanged thumbnails. RAW source colour remains unavailable rather than inferred from its preview. Tests cover layout, missing metadata, edit refresh, profile removal/backfill/reopen and narrow/list visual baselines.

Folders navigation fills the available sidebar width (D42), including All/Unassigned, device headers and indented folder names. Disclosure arrows remain separate; long names truncate with hover text. Headless checks cover right-edge selection, nesting, collapse/reopen, both themes and display scales; screenshots cover device headers in both themes.

Desktop legibility (D33) uses larger interface/caption text and List metadata, stronger normal/secondary/selection contrast in both themes, hinted glyphs without fractional variants, and roomier rows. Native display scaling is preserved. Layout checks cover both themes at 1×/1.5×/2×; light and Retina List screenshots supplement existing baselines.

Desktop release automation (D34) exists for published releases: Windows x64/ARM64 ZIPs, macOS ARM64 `.app` + CLI archive, and Linux x86-64 Debian `.deb`, Fedora `.rpm` and Arch `.pkg.tar.zst`. Manual dispatch produces workflow artifacts only by default; `release_tag` builds the tag's application with current workflow packaging and uploads to its existing release. Hosted v0.1.0 recovery passed all four builds, all three Linux installation checks and final upload. All six assets and SHA256SUMS are published and their digests verified. Arch constraints are guarded by a generated-metadata regression. macOS Intel/universal releases are no longer targeted. Developer ID signing/notarization and Windows publisher signing remain open; NAS musl/Docker packaging remains planned.

## 4. Next


- **M3 sync, D20 slice** (decided, not built) — implement the target model: generation bump on any catalogue write; annotation-delta push with a per-item conflict policy; preview generation with the per-catalogue store (embedded vs external); `GET /preview/<sha>`; retire the whole-snapshot push. Testable on this machine. See D20 and `docs/sync.md`.
- **M3 sync, deployment half** — the musl build and Docker packaging (`packaging/`) for `icatalog serve` on a NAS (D18 built the service itself). Exit criteria: a static musl build, a compose example, gate passes. Not verifiable on this machine (no musl target, no cross linker, no Docker).
- Then close the M2/M3 gaps above; `wasm32-unknown-unknown` install and the first wasm check join the gate once the target is available.
